# Cinematic site kit

Нейтральный каркас для навыка CinematicSite. Здесь нет готового визуала: разделы, мир, шрифты, палитра и движение приходят из выбранного направления. Токены и раскрытия — заглушки, которые заменяются при сборке сайта.

В комплекте Astro, контракт загрузки, базовые стили, локализация, превью-сервер, проверка сборки и генератор нейтральных заглушек. Three.js и готовые 3D-сцены добавляются в проект по выбранному направлению.

## Новый сайт

```bash
bun ../Tools/NewSite.ts --name my-site --brand "My Brand" --dir /tmp/my-site --no-git
```

## Команды

```bash
bun run dev               # разработка
bun run build             # проверка типов и боевая сборка в dist/
bun run build:preview     # сборка с PUBLIC_PREVIEW=1; обработку этой переменной добавляет конкретный сайт
bun run verify            # ссылки dist, форма текстов всех языков; --release — без следов каркаса и с переводами
PORT=<порт> bun run preview   # dist/ с noindex; без PORT — случайный свободный порт. Занятый порт = чужое превью
bun run media             # заглушки: --accent/--warm/--bg из направления, --list "имя:ШxВ,…", --reel для ролика
```

Скрипты и стили всегда отдельными файлами в `_astro/` (`assetsInlineLimit: 0` в `astro.config.mjs`): проверка запасных путей блокирует их по адресу, выкат сверяет страницы по ним.

Каркас не подменяет домен и не создаёт API-прокси автоматически. Запрет индексации задаётся HTTP-заголовками комплектного preview-сервера; при размещении `dist/` на другом хостинге его нужно настроить там отдельно. Лицензия MIT лежит в `LICENSE` и сохраняется при копировании каркаса.

## Контракт загрузки

`<html class="no-js">` → `js` в первом инлайн-скрипте; через 4,5 с без `ui-ready` ставится `ui-failed`, и весь текст показывается; `src/scripts/boot.ts` ставит `ui-ready`. Раскрываемые элементы (`data-reveal`, `data-split`) видимы без JS и при `ui-failed`. На этот контракт опирается проверка скилла (`Tools/Check.ts`).
